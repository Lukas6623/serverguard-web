Используются обычные HTML, CSS и JavaScript, DOM API, Fetch API, Canvas 2D,

JS модулей регистрируется в `window.ServerGuard`.

## Связь с приложением

Frontend делает относительные запросы `/api/...` на том же origin, что
и страница. Основная функция `api()` сериализует запросы в очередь, передаёт
`credentials: "same-origin"` и JSON для запросов с телом. Dashboard и
FileGuard используют отдельные вызовы fetch, минуя эту очередь.

При 401 интерфейс предлагает открыть ссылку с токеном из консоли ServerGuard.
Как именно приложение проверяет токен/выдаёт cookie, из frontend не видно.
В frontend нет SSH-клиента, подключения к удалённому серверу, выбора сервера
или endpoint для создания SSH-сессии. Предполагаемая цепочка «браузер →
локальный backend → выбранная SSH-сессия → удалённый Linux» соответствует
назначению панели, но реализация последних двух звеньев отсутствует.

Порт 8765 сейчас обслуживается Python `SimpleHTTP/0.6`, PID 90575 на момент
проверки. Это статический сервер, запущенный в предыдущей работе, а не
backend установленного приложения. Его 404 не доказывают, что этих endpoint
нет в полной версии ServerGuard.

## Online/Offline и доступность модулей

1. `core.js`: `/api/health` при запуске и каждые 10 секунд. 401 показывает
   «нет доступа»; успешный разбор любого другого JSON включает «ServerGuard
   онлайн». Проверки `response.ok` и состояния SSH-сессии нет.
2. Встроенный JS Dashboard: успешный HTTP-ответ и JSON от
   `/api/server/stats` вызывают `setConnected(data)` без проверки содержимого.
   Ошибка вызывает `setDisconnected()`. Оба механизма меняют `connDot` и
   `connText`, поэтому результат зависит от порядка ответов.
3. `/api/modules` загружается только при успешной начальной проверке health.
   Модуль доступен в навигации, если значение `moduleState[id]` истинно
   и его секция существует в DOM. После восстановления backend автоматической
   повторной загрузки списка модулей нет. Недоступные модули подписаны «скоро»,
   хотя это может означать отсутствие связи или отключённый модуль.
4. Большинство модулей обновляют статус каждые 15 секунд при выбранной вкладке,
   включённом auto-refresh и видимом документе. FileGuard использует 5 секунд
   и отдельные состояния загрузки/занятости. Его root — сама секция
   `section#fg-root[data-module="fileguard"]`; проверка `root.hidden`
   учитывает переключение вкладок через общий загрузчик.

Сейчас ни один модуль нельзя подтвердить как работающий с удалённым сервером:
все проверенные API отвечают 404. Реализован именно frontend пяти модулей.

## Найденные проблемы

- Доступность локального HTTP backend и подключение удалённого сервера
  смешаны; единого источника состояния соединения нет.
- Health может объявить online даже JSON-ответ 500 или JSON с ошибкой.
  Dashboard объявляет online даже пустой JSON-объект, не проверяя сервер.
- При потере связи Dashboard не очищает предыдущие метрики, hostname и
  информацию о сервере. На экране могут остаться устаревшие значения.
- Отсутствующая скорость одного направления сети подменяется нулём;
  невалидная скорость также форматируется как `0 B/s`. Это не подтверждённые
  реальные измерения.
- Для OS и hostname есть подставляемые названия Linux/Linux Server, а
  успешное получение метрик связывается с надписью PROTECTED. Само получение
  метрик не подтверждает состояние защиты.
- Глобус использует фиксированные города, серверы, пользователей и связи;
  всплывающая подпись «Protected» не поступает из API. Это декоративная
  визуализация, которую сейчас можно принять за реальную инфраструктуру.
- В заголовок Dashboard hostname вставляется через `innerHTML` без
  экранирования. Полученные данные следует выводить через `textContent`.
- Опрос метрик не имеет тайм-аута, блокировки параллельных запросов и паузы
  при скрытом документе; медленные ответы могут приходить в неверном порядке.
- Общая `api()` скрывает ошибки разбора JSON, заменяя ответ на `{}`.
- Неизвестный/отсутствующий статус и актуальная ошибка не везде отделены
  от прежнего статуса модуля; кнопки могут опираться на старые данные.
- На Dashboard нет ручного обновления и времени последнего успешного
  получения данных. Loading, empty и offline оформлены непоследовательно.
- Метрики идут после крупного глобуса, sidebar занимает 250 px,
  текущая палитра преимущественно голубая. Иерархия и единая фиолетовая
  дизайн-система ещё не реализованы.
- Адаптивные CSS-правила существуют, но соответствие 360/768/1440 px и
  клавиатурная доступность не подтверждены браузерным тестом.
- README не соответствует активному FileGuard, а две копии frontend могут
  разойтись при последующих изменениях или упаковке.
