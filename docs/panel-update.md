## Визуальные изменения

- Применены background `#08060f`, surface `#131022`, accent `#8b5cf6`,
  secondary accent `#d946ef`, text `#f1eefb` и общие цвета статусов.
- Sidebar уменьшен с 250 до 220 px. У разделов единые отступы,
  декоративные значки, активный пункт и объяснение недоступности.
- Важные метрики расположены сразу под заголовком; глобус находится
  ниже, рядом с информацией о сервере. Высота его контейнера примерно
  230–260 px вместо прежних 500–760 px.
- Карточки, заголовки, кнопки, поля, вкладки, логи, таблицы FileGuard,
  подтверждения и ошибки оформлены общими токенами.
- Сохраняются Canvas, вращение, перетаскивание и существующие анимации.
  Клавиши стрелок и Home управляют поворотом глобуса. Существующая
  поддержка reduced motion сохранена и дополнена для новых эффектов.
- Добавлены адаптивные правила: мобильная навигация сеткой,
  переносы элементов управления, сетки с `minmax(0, ...)`, перенос длинных
  имён/сообщений и внутренний скролл таблиц. Реальный layout требует
  проверки в браузере.

## Исправления UX и данных

- `dashboard.js` — единственное место, рисующее Online/Offline сервера.
  `core.js` больше не объявляет сервер Online по одному `/api/health`.
- Начальное состояние — OFFLINE с прочерками. При ошибке получения
  данных очищаются CPU, RAM, Disk, Uptime, Network, hostname и сведения
  о сервере; время прошлого обновления явно подписано отдельно.
- Неизвестные, null, пустые и отрицательные скорости не подменяются нулём.
  Настоящий ноль из API сохраняется. Если есть только одно направление,
  второе отображается как «—». Прежний fallback общего трафика сохранён.
- Убраны подставленные OS/hostname и неподтверждённая надпись PROTECTED
  из Dashboard. Города глобуса подписаны как декоративные точки;
  видимая подпись объясняет, что линии не отражают реальные подключения.
- Данные API, включая hostname, выводятся через `textContent`.
- Добавлены ручное обновление, время успешного ответа, индикатор
  ожидания, сообщения HTTP/401/ошибок JSON и восьмисекундный тайм-аут.
- Запросы Dashboard не перекрывают друг друга. Опрос приостанавливается
  в скрытом документе и возобновляется после возвращения. Повторный
  запрос метрик выполняется через 3 секунды после завершения предыдущего;
  health проверяется примерно раз в 10 секунд и при ручном обновлении.
- После потери доступности backend сбрасывается кэш модулей.
  Восстановление связи, ручное обновление и восстановление получения
  метрик повторяют `/api/modules`. Ошибка списка модулей также повторяется
  при следующем опросе. Старый ответ до отключения не включает модули заново.
- Доступность по-прежнему определяется прежними значениями `/api/modules`,
  наличием секции и теперь также успешной регистрацией её JS. Недоступные
  разделы не включаются искусственно; вместо «скоро» показывается причина.
- Для модулей добавлены начальные placeholders без подставных значений.
  Сохранены native buttons, видимый focus и Escape в диалоге;
  навигация сохраняет фокус при перестроении. Есть skip-link к main.

## Что сохранено и что означает ONLINE

Сохранены SSH Key Guard, Security, Telegram Bot, SSH Hardening и FileGuard,
их формы, обработчики действий, журналы, диалоги и обновление статуса.
Управляющие операции и условия их подтверждений не переписывались.
Автоматическое выполнение управляющих операций не добавлялось.

Используются только прежние `/api/health`, `/api/modules`,
`/api/server/stats` и неизменённые модульные запросы. JSON-тела управляющих
запросов и прежние поля/алиасы метрик сохранены. Для health не введена
новая обязательная объектная схема ответа. Новых HTTP API нет.

ONLINE опирается на прежнее предположение frontend: успешный health
и успешный ответ `/api/server/stats` с известными непустыми полями.
Пустой объект, HTTP-ошибка или явная ошибка ответа не включают ONLINE.
Это **не независимая проверка SSH-сессии**: backend и его признак
выбранного/подключённого сервера отсутствуют. Поля `connected`, `server_id`
и другие неподтверждённые поля не придумывались.

Если настоящий backend отдаёт кэш старого сервера после SSH-отключения,
frontend не сможет достоверно выявить это без контракта backend.
Доступность модулей подтверждается `/api/modules`, а не наличием системных
метрик: отсутствие stats endpoint не отключает ранее поддерживаемые
backend модули. Доступность API явно отделена от получения данных сервера.

Никакие показатели локального компьютера не собираются. Данные-заглушки
есть только в изолированных тестах и не подключены к панели.

## Что осталось проверить

Браузерный инструмент вернул пустые списки приложений и браузеров.
Поэтому отрисовка 360/768/1440 px, фактическое отсутствие горизонтального
переполнения, Canvas, реальные Tab/Enter/стрелки, screen reader и отсутствие
runtime/console-ошибок в настоящем браузере **не проверены**. CSS-разбор
и тесты с DOM-заглушками этого не доказывают.

Без настоящего backend и разрешённого тестового удалённого сервера
невозможно подтвердить действующее SSH-подключение, привязку метрик
к выбранному серверу, единицы измерения, реакцию на реальное отключение,
совместимость новых проверок ответов и реальную работу операций модулей.
POST-запросы при проверке не выполнялись. Регрессионный прогон CLI
не выполнялся; исходники CLI и установленный бинарник не менялись.
